* アーキテクチャ概要

** 全体像

SLIME（Common Lisp）と Claude Code（agent-shell 経由）を双方向に連携させるグルーコード。

設計の核は「変更通知 layer を agent-shell 本体に持ち、その上に SLIME 等の個別サポートを乗せる」構造。
通知チャネルは agent-shell の prompt-queue（プロンプト直前の受動的注入ではなく、
変更が起きた時点でエージェントに能動的に伝える）。

#+begin_example
変更イベント源
  after-save-hook（既知ファイル保存）──►┐
  slime-eval (C-c C-c 等)           ──►│  agent-shell--notify-*
  elisp-eval (C-M-x 等)             ──►│  ↓
  (future: sly)                    ──►│  agent-shell--prompt-queue
                                       │  （busy なら enqueue、idle なら即送信）
                                       ↑
             agent-shell 自身の保存は agent-shell--suppress-save-notification で除外
             (:known-files で「エージェントが知っているファイル」のみ対象)

  ┌──────────────────────────────────────────────────────────┐
  │ 3方向の連携（agent-shell-slime.el コア）                   │
  │                                                          │
  │ ① C-c C-c (slime-compile-defun)                          │
  │      └─► CL image（SLIME 本来の動作）                     │
  │      └─► cl-mcp HTTP エンドポイント（repl-eval ツール）    │
  │      └─► agent-shell--notify-eval（eval 結果を通知）       │
  │                                                          │
  │ ② Claude がファイル保存                                   │
  │      └─► after-save-hook + SLIME 接続中なら               │
  │          slime-compile-and-load-file 自動実行             │
  │                                                          │
  │ ③ M-x agent-shell-slime-ask (C-c C-')                    │
  │      └─► カーソル下の defun を取得                        │
  │      └─► agent-shell--insert-to-shell-buffer に送信       │
  │          （fallback: kill-ring へコピー）                  │
  └──────────────────────────────────────────────────────────┘
#+end_example

** upstream branch との関係

=remotes/origin/claude/auto-revert-global-minor-mode-xzfue5= に、
ファイル変更通知 layer の実装（2026-08-02、Author: Claude）がある。
未マージで PR もないが、main への衝突ゼロ。我々の実装はこれに乗る。

upstream branch が実装している部分：
- =:known-files= をセッション state に追加（=fs/read_text_file= / =fs/write_text_file= 呼び出し時に記録）
- =agent-shell--suppress-save-notification= dynamic variable（agent 自身の保存を除外）
- =agent-shell--notify-file-changed=（prompt-queue か即送信に振り分け）
- =agent-shell--notify-known-file-changed=（=after-save-hook= 関数）
- =agent-shell-notify-known-file-changes-mode=（global minor mode、default ON）

我々が追加する部分：
- =agent-shell--notify-eval=（SLIME eval 結果を同じ経路で通知する関数）
- =agent-shell-slime.el=（方向①②③、MCP ツール登録）

** ファイル構成

| ファイル | 内容 | 場所 |
|----------+------+------|
| =agent-shell-context-sources.el= | 変更キュー + file-watcher + elisp-eval + context injection（汎用） | agent-shell リポジトリ（PR 対象） |
| =agent-shell-slime.el=（仮称） | SLIME/CL 特化部分（方向①②③、MCP ツール登録） | 同リポジトリまたは別 package |

=agent-shell-context-sources.el= は既存の =agent-shell-context-sources= defcustom 変数名と
一致しており、「コンテキストソースの拡張モジュール」として名前が体を表している。

関数プレフィックス：
- 公開 API :: =agent-shell-context-sources-=
- 内部関数 :: =agent-shell-context-sources--=

初期 PR は汎用部分（変更キュー + file-watcher）に絞り、SLIME 特化部分は
=agent-shell-slime.el= に分離する。

** フェーズ 1: agent-shell-slime.el コア（3方向）

最小構成。~60行規模。cl-mcp と SLIME に直接依存。

*** 方向①：ユーザー編集 → CL image & Claude context

=slime-compile-defun=（=C-c C-c=）に =advice-add= でフックを追加する。
SLIME 本来の挙動（CL image への送信）はそのまま維持し、追加で
cl-mcp の HTTP エンドポイントに非同期 POST する。

#+begin_src emacs-lisp
(defvar agent-shell-slime-cl-mcp-port 3000
  "cl-mcp HTTP サーバーのポート番号。")

(defun agent-shell-slime--send-to-cl-mcp (form)
  "FORM を cl-mcp の repl-eval ツールへ非同期 POST する。"
  (let ((url (format "http://127.0.0.1:%d/mcp" agent-shell-slime-cl-mcp-port))
        (payload (json-encode
                  `((:jsonrpc . "2.0")
                    (:method . "tools/call")
                    (:id . 1)
                    (:params . ((:name . "repl-eval")
                                (:arguments . ((:code . ,form)))))))))
    (let ((url-request-method "POST")
          (url-request-extra-headers '(("Content-Type" . "application/json")))
          (url-request-data payload))
      (url-retrieve url #'ignore nil t))))

(defun agent-shell-slime--after-compile-defun (&rest _)
  "slime-compile-defun 後に同じフォームを Claude コンテキストへ送る。"
  (when-let* ((form (thing-at-point 'defun t)))
    (agent-shell-slime--send-to-cl-mcp form)))

(advice-add 'slime-compile-defun :after #'agent-shell-slime--after-compile-defun)
#+end_src

*** 方向②：Claude 編集 → CL image（自動ロード）

=after-save-hook= に追加。lisp-mode バッファかつ SLIME 接続中のときのみ発火。

#+begin_src emacs-lisp
(defun agent-shell-slime--auto-load-on-save ()
  "Claude がファイルを保存したとき、CL image に自動ロードする。"
  (when-let* (((derived-mode-p 'lisp-mode))
              ((slime-connected-p))
              (file (buffer-file-name)))
    (slime-compile-and-load-file)))

(add-hook 'after-save-hook #'agent-shell-slime--auto-load-on-save)
#+end_src

*** 方向③：エディタ → Claude への指示（agent-shell-slime-ask）

カーソル下の defun を agent-shell のシェルバッファに送信する。

#+begin_src emacs-lisp
(defvar agent-shell-slime-shell-buffer nil
  "連携先の agent-shell バッファ。nil の場合は kill-ring にフォールバック。")

(defun agent-shell-slime-ask ()
  "カーソル下の defun を Claude に送信する（C-c C-'）。"
  (interactive)
  (when-let* ((form (thing-at-point 'defun t)))
    (if (and agent-shell-slime-shell-buffer
             (buffer-live-p agent-shell-slime-shell-buffer))
        (agent-shell--insert-to-shell-buffer
         :text (format "次の Common Lisp フォームを確認・改善してください:\n\n```lisp\n%s\n```" form)
         :buffer agent-shell-slime-shell-buffer)
      (kill-new form)
      (message "agent-shell バッファ未設定。フォームを kill-ring にコピーしました。"))))
#+end_src

*** claude-code-ide.el 経由の MCP ツール登録（オプション）

=claude-code-ide.el= が利用可能な場合、Claude 側から CL を eval できる
ツールを2つ登録する。

| ツール名 | 動作 |
|----------+------|
| =slime_eval_form= | 任意の CL form を SLIME 経由で eval |
| =slime_load_current_file= | 現在の .lisp バッファを compile & load |

#+begin_src emacs-lisp
(with-eval-after-load 'claude-code-ide
  (claude-code-ide-make-tool
   "slime_eval_form"
   "Common Lisp フォームを SLIME 経由で評価する"
   '(("form" "string" "評価する CL フォーム文字列"))
   (lambda (args)
     (slime-eval `(swank:eval-and-grab-output ,(map-elt args "form")))))

  (claude-code-ide-make-tool
   "slime_load_current_file"
   "現在の .lisp バッファをコンパイルして CL image にロードする"
   '()
   (lambda (_args)
     (slime-compile-and-load-file))))
#+end_src

** フェーズ 2: eval 通知の追加（upstream layer への乗り乗り）

upstream branch の file-change 通知 layer の上に、eval 系イベントを追加する。
通知チャネルは upstream と同じ =agent-shell--notify-file-changed= / prompt-queue 経路を踏む。

ファイル変更の通知インフラ（=:known-files=、=agent-shell--suppress-save-notification=、
=agent-shell--notify-file-changed=、=agent-shell-notify-known-file-changes-mode=）は
upstream branch が提供するため、ここでは実装しない。

*** agent-shell--notify-eval（新関数）

file-changed と対称な、eval 結果の通知関数。
=agent-shell-slime.el= 内で呼ぶ（agent-shell 本体への PR 候補でもある）。

#+begin_src emacs-lisp
(cl-defun agent-shell--notify-eval (&key shell-buffer form result)
  "SHELL-BUFFER に FORM を eval した旨を通知する。RESULT は省略可。

busy なら prompt-queue に積み、idle なら即送信する。
agent-shell--notify-file-changed と同じ振り分けロジック。"
  (with-current-buffer shell-buffer
    (let ((note (if result
                    (format "Note: evaluated:\n\n%s\n\n=> %s" form result)
                  (format "Note: evaluated:\n\n%s" form))))
      (if (shell-maker-busy)
          (agent-shell--prompt-queue-enqueue :prompt note)
        (agent-shell--insert-to-shell-buffer :text note :submit t :no-focus t)))))
#+end_src

*** slime-eval ソース（agent-shell-slime.el 内）

=agent-shell--notify-eval= を呼ぶ advice。
どの shell buffer に送るかは =agent-shell-slime-shell-buffer= から引く。

#+begin_src emacs-lisp
(defun agent-shell-slime--after-slime-eval (&rest _)
  "SLIME eval 後にエージェントへ通知する。"
  (when-let* ((buf agent-shell-slime-shell-buffer)
              ((buffer-live-p buf))
              (form (thing-at-point 'defun t)))
    (agent-shell--notify-eval :shell-buffer buf :form form)))

(dolist (cmd '(slime-compile-defun slime-eval-last-expression slime-eval-defun))
  (advice-add cmd :after #'agent-shell-slime--after-slime-eval))
#+end_src

**** eval 結果の取得（オプション）

SLIME eval は =slime-eval= が非同期のため、結果を =:result= に渡すには
コールバック経由になる。まず form のみ通知する単純版で実装し、
結果付き通知は後続の拡張候補とする。

*** elisp-eval ソース

Emacs Lisp eval 系コマンドに advice。slime-eval と対称。

#+begin_src emacs-lisp
(defun agent-shell-slime--after-elisp-eval (&rest _)
  "Elisp eval 後にエージェントへ通知する。"
  (when-let* ((buf agent-shell-slime-shell-buffer)
              ((buffer-live-p buf))
              (form (thing-at-point 'sexp t)))
    (agent-shell--notify-eval :shell-buffer buf :form form)))

(dolist (cmd '(eval-defun eval-last-sexp eval-region eval-buffer))
  (advice-add cmd :after #'agent-shell-slime--after-elisp-eval))
#+end_src

* テスト方針

** 配置場所

=tests/agent-shell-tests.el=（agent-shell 既存のテストファイルに追記する。
upstream branch も同ファイルにテストを追加している）

** テスト項目

file-change layer（フェーズ 0）は upstream branch に既にテストがある。
追加するテストはフェーズ 2 分のみ。

| テスト | 手法 |
|--------+------|
| =agent-shell--notify-eval= idle 時即送信 | =shell-maker-busy= をモック（nil）、=agent-shell--insert-to-shell-buffer= の呼び出しを検証 |
| =agent-shell--notify-eval= busy 時 enqueue | =shell-maker-busy= をモック（t）、=agent-shell--prompt-queue-enqueue= の呼び出しを検証 |
| slime-eval advice の発火 | =slime-compile-defun= 後に =agent-shell--notify-eval= が呼ばれること |
| =agent-shell-slime--send-to-cl-mcp= | =url-retrieve= をモックして POST ペイロードを検証 |

** 手動検証手順

1. SBCL を起動し、=cl-mcp:start-http-server :port 3000= で HTTP サーバーを起動
2. Emacs で SLIME 接続（=M-x slime=）
3. .lisp バッファで任意の defun を書き、=C-c C-c= を実行
4. cl-mcp のログで =repl-eval= ツール呼び出しが届いていることを確認
5. agent-shell で次のプロンプトを送信し、変更キューのコンテキストが注入されることを確認
